# Bilingual output — what is translated, and what never is

**6 November 2026.** Condition **C-6** of
[`V1_CANDIDATE.md`](V1_CANDIDATE.md).

```sh
python verify.py <archive> --corpus <corpus> --lang en
python verify_attestation.py <attestation> --archive <archive> \
  --trust-store <store> --lang en
python timestamp.py verify <proof> --subject <file> --lang en
python bind.py verify <manifest> --archive <archive> --lang en
python adapters/reconcile.py <receipt> --archive <a> --map <m> --lang en
```

Default is `fr`. The default output is unchanged, byte for byte.

On the tools with subcommands, `--lang` is declared on a **parent** parser,
so it can be written after the subcommand — which is how one writes it.

---

## What `--lang` never touches

Four things are identical in both languages, by contract:

| | Why |
|---|---|
| **The states** — `PASS`, `FAIL`, `NOT TESTED` | contractual terms, not prose. Translating them would break every consumer. |
| **The exit codes** — 0, 1, 2 | they depend on verdicts, not on language |
| **JSON report field names** | already contractual, and already English |
| **Digests, identifiers, file names, measured values** | they pass through **verbatim**. A translated digest would be a false digest. |

The assurance level is in the same class: `cryptographically_attested` stays
`cryptographically_attested` in both. A consumer that string-compares the
level must keep working.

## Coverage — measured, not asserted

This is the part that matters, and it is why the condition can be reported
honestly.

The catalogue does not *declare* itself complete. `tests/test_i18n.py`
**exercises the tools and fails if a single line comes out with
untranslated French prose**:

| Case | What it measures |
|---|---|
| 7 | no residue on a valid archive |
| 13 | no residue across **7 failure regimes** — altered member, missing manifest, broken manifest, unknown schema, missing checksums, not-a-ZIP, not-found |
| 19 | no residue on the attestation verifier |

Case 13 earned its place: a manual sweep found a real residue
(`manifest.json n est pas du JSON lisible`) that case 7 could not see,
because French prose lives mostly in the **failure paths** — that is where a
control explains what is missing.

And the invariants are checked in both directions:

| Case | Invariant |
|---|---|
| 1, 15 | same number of control lines |
| 2, 16 | **same states, in the same order** |
| 3, 4, 17, 18 | same exit code, normal and `--strict` |
| 5 | digests identical, to the character |
| 6, 6b | JSON report: same field names, same counts |
| 8 | without `--lang`, the French output is **unchanged** |
| 10 | without `i18n.py`, same verdicts, in French |
| 14 | same states and codes across the 7 failure regimes |
| 20 | the level is never translated |

Case 2 is the one that guards against the only real risk of this work: a
verdict shifting with the language.

## Scope — what is bilingual, and what is not

Stated plainly, because half of the tools are not.

| Tool | Output | Scope |
|---|---|---|
| `verify.py` | **FR + EN** | the 21 integrity controls |
| `verify_attestation.py` | **FR + EN** | the 14 attestation controls, the five pillars, the level |
| `timestamp.py` | **FR + EN** | `stamp`, `inspect`, `verify`, `upgrade` |
| `bind.py` | **FR + EN** | `build` and `verify`, the four assurance levels |
| `adapters/reconcile.py` | **FR + EN** | the five statuses, the comparability boundaries |
| `adapters/receipt_import.py` | **FR + EN** | the import of an external receipt |
| `sign.py` | **FR + EN** | `genkey` and `attest` |

**C-6 is RESOLVED.** All seven tools take `--lang {fr,en}`, and coverage is
measured across 13 scenarios spanning valid paths, failure paths and
missing arguments — case 21 of the suite.

Catalogue: **188 exact strings, 208 formats**.

### One thing deliberately NOT translated

Beyond the four contractual classes above: the **Markdown report**
`reconcile.py` writes with `--report`. It is a file artifact rather than
verifier output, and it is still produced in French. Named here because
nothing else says so.

### How the 147 call sites were converted

Not by hand. Every `print(` became `dis(`, a function that translates its
format before printing. The rename is mechanically exact, and that was
**verified before doing it**: in each of the five files, the number of
occurrences of the text `print(` equals the number of real call nodes in
the AST — so no occurrence lived inside a comment or a docstring.

The language travels in a module-level cell, set once by `main()`. The
alternative — passing the language as an argument — would have meant
editing 147 signatures instead of renaming 147 calls. A rename can be
read back; 147 changed signatures cannot.

---

## How it works, and why it was built this way

**No call site was modified.** The 52 `dire()` sites in `verify.py` build
their label and detail in French exactly as before; `Bilan.dire` translates
just before printing.

That choice has one reason: converting 52 call sites into catalogue
identifiers would have touched verification logic three days before an
external review, for no gain — the prose would read the same. This way, not
one line of logic moved.

The price: at emission time only the **already-formatted** string is
visible. Hence two stages:

1. **Exact** — the whole string is in the catalogue. Covers fixed labels and
   literal details.
2. **Pattern** — the string was produced by a known format. A regular
   expression is derived from the French format, the arguments are extracted
   and re-injected into the English one. Those arguments are the data, and
   they come out unchanged.

A text argument is itself submitted to the catalogue: prose gets translated,
data does not — because the catalogue contains only prose, so no exception
list is needed.

If neither stage answers, the French string is emitted as-is. That is a net,
and the cases above measure that the net is not used.

### Translation is optional

`verify.py` and `verify_attestation.py` import `i18n` **softly**. Without
`i18n.py` beside them they still run, return the same verdicts and the same
exit code, in French. An auditor can copy a single file. The integrity
controls must never depend on the translation layer — case 10 verifies it.

## The data rule — what must never be translated, and why

`reconcile.py` prints text that is **not ours**: the labels of the
partner's receipt, and the free text of the correspondence table (`basis`,
`not_comparable_reason`). Translating those would stop the report from
naming what the partner wrote — which is to say, it would falsify it.

The rule that settles it, and that is checkable: **a string appearing
verbatim in an input file is data, not prose.**

Case 23 verifies it in the other direction. It requires that at least one
such string exist and come out **unchanged** — so that "it's data" cannot
become an excuse for anything left untranslated.

## Two defects this work surfaced

Worth recording, because both were caught by measurement rather than
inspection.

1. **A `%r` capture already carries its quotes.** Re-injecting it into an
   English `%r` double-quoted it: `schema "'inconnu'"`. Captured values are
   now never reformatted — the same rule that protects digests and counts.
2. **The residue detector was pointed at the wrong output.** It asks "would
   this *French* string come out untranslated?", and it was being fed the
   *English* output — so it flagged 27 already-translated English strings
   and zero real residues. It now compares the two outputs line by line.
